# M40 — 비용 관측·라우팅: 검증자 비용 계측 + 저비용 우선 모델 승급

## 목표

함대의 **전체 비용이 보이고, 비용에 따라 모델을 자동 선택**한다. 끝나면: 그동안 누락됐던
**검증자(verifier) LLM 비용**이 계측되어 감사·리포트·대시보드에서 dispatch 비용과 분리 노출되고,
task는 **저비용 모델로 먼저 시도**하되 재투입(실패) 시 **강한 모델로 승급**해 쉬운 작업의 비용을
줄이면서 어려운 작업의 성공률을 지킨다.

## 배경

retro(2026-06-11, v0.35.0 시점)가 집계한 **뿌리 B — "비용이 절반만 보인다"**를 닫는다. 구체적 출처:

- **검증자 비용 미계측** (현행 코드): dispatch는 `run_agent`(→`run_agentic_metered`)로 비용을
  계측하지만, **검증은 `verify::run_verification`이 비메터드 `run_agentic`을 호출**해 출력 문자열만
  받는다(`verify.rs:319,332`). 1차 심사 + 재질의의 검증자 LLM 비용이 **전부 소실**된다. 감사
  `conductor-4`·`report::total_cost`는 dispatch 비용만 합산한다.
- **라우팅 근거 부족** (retro 회고 메모 1, "계측이 라우팅의 선행"): 전체 비용이 안 보이니 "어떤
  모델을 언제 쓸지" 판단 근거가 없다. dispatch 모델은 `effective_model` 하나로 고정 — 쉬운 task도
  강한(비싼) 모델로 한 번에 간다.
- **저비용 우선·실패 시 승급** (retro 후보 B2): 재투입(M37/M39)이 이미 "실패 → 재시도" 신호를
  주므로, **재투입 횟수를 모델 승급 트리거**로 쓰면 자연스럽게 "쉬우면 싸게, 어려우면 강하게"가 된다.

기존 자산 재사용: `run_agentic_metered`(→`AgentRun{cost_usd,input/output_tokens}`), 감사 기록
스키마(`conductor-4`, 하위호환 — 구 파서는 없는 필드를 None 처리), 리포트 집계(`total_cost`·
`sum_opt_f64`), 재투입 루프(redispatch 카운트). 설계 불변: 무결합·하위호환(스키마 가산).

## 태스크 상세

### M40-T01: 검증자 비용 계측

**변경 파일**: `src/conductor/verify.rs`, `src/conductor/mod.rs`, `src/conductor/parallel.rs`, `src/conductor/report.rs`

- `verify.rs`: `run_verification`의 `run_agentic`(2곳: 1차·재질의)를 **`run_agentic_metered`**로 교체,
  반환 `AgentRun`의 `cost_usd`를 누적. `VerifyOutcome`에 `verifier_cost_usd: Option<f64>`(+ 선택적
  `verifier_input/output_tokens`) 추가. chaos·diff-empty·명령 실패 등 LLM 미호출 경로는 None/0.
- `mod.rs`: `conduct_in_worktree`에서 task_cost에 **dispatch + verifier 비용 합산**. `write_audit_record`에
  `verifier_cost_usd` 필드 추가, `schema_version`을 **`conductor-5`**로(구 파서 하위호환 — 없는 필드 None).
  기존 VerifyOutcome 생성 지점(테스트 포함) 필드 보강.
- `parallel.rs`: 병렬 경로도 verifier 비용을 total_cost·감사에 반영(write_audit_record 공유).
- `report.rs`: `AuditRecord`에 `verifier_cost_usd`(serde default None) 역직렬화, `TaskReport`에 분리
  집계, `total_verifier_cost()`·필요 시 `total_dispatch_cost()` 추가. `total_cost`는 **dispatch+verifier
  합**으로 정의(또는 분리 노출 — 합계 의미 명확화). 단위 테스트로 합산·하위호환(구 conductor-4 레코드는
  verifier_cost None) 검증.

### M40-T02: 비용 기반 모델 라우팅 — 저비용 우선·실패 시 승급

**변경 파일**: `src/config/workspace.rs`, `src/conductor/mod.rs`, `src/conductor/parallel.rs`

- `[conductor] dispatch_model_fast`·`verifier_model_fast`(Option<String>, 빈 값 None) + getter. 미설정이면
  라우팅 비활성(기존 동작 — 항상 strong 모델).
- 순수 헬퍼 `route_model(strong: Option<&str>, fast: Option<&str>, attempt: u32) -> Option<&str>`:
  `attempt == 0 && fast.is_some()` → fast, 아니면 strong. **단위 테스트**(승급 경계·fast 미설정 폴백).
- **순차**(`conduct_in_worktree`): dispatch 모델을 `route_model(dispatch_strong, dispatch_fast, redispatch)`로,
  verifier 모델을 `route_model(verifier_strong, verifier_fast, redispatch)`로 매 라운드 선택. 승급 시
  "↑ 모델 승급" 1줄 안내.
- **병렬**(`dispatch_batch_parallel`): task별 `attempts`(현 시도 횟수)로 같은 라우팅. dispatch_model은
  현재 고정 인자 → task별 계산으로 변경.
- 하위호환: fast 미설정이면 strong만 사용(현행과 동일). `effective_model`=strong dispatch 기준.

### M40-T03: 대시보드 — 검증자 비용 분리 노출 + 라우팅 설정 (deps: M40-T01, M40-T02)

**변경 파일**: `src/dashboard/api.rs`, `src/dashboard/static/{app.js,index.html}`, `src/dashboard/config_edit.rs`

- 리포트 롤업: 총비용을 **dispatch / verifier 분리**로 표시(또는 총합 + 분리 툴팁). `report_json`에
  `total_verifier_cost` 추가, task 상세(`/api/task`)의 라운드에 `verifier_cost_usd` 노출(M36 패턴).
- 설정 폼: `dispatch_model_fast`·`verifier_model_fast`(text) 추가. `config_edit` `EDITABLE_KEYS`·검증
  (text_safe)·GET 노출에 두 키 추가.
- esc() XSS 규약·기존 시각 회귀 없음 유지.

### M40-T04: 문서 + 하니스 (deps: M40-T01, M40-T02, M40-T03)

- 하니스(claude 불필요): 합성 conductor-5 감사 레코드(verifier_cost 포함) → `/api/report`·`/api/task`의

## 완료 기준

1. `cargo build` 경고 0개, `cargo clippy` 신규 경고 0개, `cargo test` 전체 통과.
2. 검증자 LLM 비용이 계측되어 task 비용·`total_cost`·감사(`conductor-5`)에 포함되고, dispatch 비용과
   **분리**해서도 집계된다. 구 `conductor-4` 레코드(verifier_cost 없음)는 None으로 하위호환 처리된다.
3. `dispatch_model_fast`(및 verifier) 설정 시 **첫 시도는 fast 모델**, 재투입(attempt>0)은 strong 모델로
   **승급**한다. 미설정이면 기존(항상 strong) 동작이 보존된다. `route_model`이 순수 함수로 단위 테스트된다.
4. 대시보드가 총비용을 dispatch/verifier로 분리 노출하고, 설정 폼에서 `*_model_fast`를 편집할 수 있다.
5. 보안 무회귀(설정 화이트리스트·검증·Origin·스코프 상속), 하위호환(스키마 가산·라우팅 미설정 시 무변경).
6. 단위·합성 하니스(verifier 비용 집계·하위호환·route_model·설정 키) 통과. 실 비용·실 승급은 운영자 라이브.
