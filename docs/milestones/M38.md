# M38 — 런처 마감: 포트 설정·런 락 정밀화·재투입 단일 버튼·설정 주석 보존

## 목표

M37 런처의 잔여 품질을 닫아 런처를 "완성" 상태로 만든다. 끝나면: 대시보드 포트가 **설정 가능**
하고(7878 하드코딩 제거), 런 락이 **죽은/끝난 자식을 정확히 인지**해 짧은 런 직후에도 즉시
재실행되며(막힘 시 강제 실행 가능), halt task를 **한 번 클릭으로 재투입+실행**하고, 설정 편집이
workspace.toml의 **주석·서식을 보존**한다. Windows에서 실증된 detached 생존을 Unix에서도
재현할 수 있는 이식 하니스를 남긴다.

## 배경

M37(v0.34.0) review·impl 보고서가 비차단 후속으로 명시한 항목들을 모은 "런처 마감" 묶음이다.
각 항목은 M37의 구체적 trade-off에서 나왔다:

- **포트 고정** — M35 내장 기동·M37 launch 경로가 포트 `7878`을 하드코딩한다(v0.32 알려진 한계
  재확인). 다른 포트로 운영하거나 충돌 회피가 불가.
- **런 락 quirk** — M37 review 권장3/impl 후속2: run.lock은 30초 시간 기반 자가 만료라, 30초
  안에 끝난 런 직후 남은 시간 동안 새 [함대 실행]이 409로 막힌다. live.json `run_active`는 이미
  false인데 락이 아직 신선해서다. 비정상 종료 시 수동 강제 수단도 없다.
- **재투입 2스텝** — M37 review 사소6: [재투입] 후 [함대 실행]을 따로 눌러야 한다.
- **설정 주석 손실** — M37 review 사소4/impl 후속3: `toml` round-trip(파싱→재직렬화)이
  workspace.toml의 주석·서식을 날린다(데이터는 보존). 기본 템플릿이 주석 다수라 체감된다.
- **Unix detach 미실측** — M37 review 잔여리스크: `process_group(0)` 경로는 std 표준이나 Unix
  라이브 실측은 미수행(`dashboard-launch-live.ps1`은 Windows 전용).

설계 불변 유지: 런 락은 **런처(대시보드) 측 관심사**로 두고 conductor를 건드리지 않는다(무결합).
설정 쓰기는 M37의 화이트리스트·검증·원자성·`utils::fs::write_file`(루트 경계)을 유지한다.

## 태스크 상세

### M38-T01: 대시보드 포트 설정화

**변경 파일**: `src/config/workspace.rs`, `src/conductor/mod.rs`, `src/dashboard/{mod.rs,config_edit.rs}`, `src/dashboard/static/index.html`

- `WorkspaceConductor`에 `dashboard_port: Option<u16>` 추가 + getter `conductor_dashboard_port() -> u16`
  (기본 `7878`, 1024~65535 범위 클램프).
- `run_conductor_inner`의 `serve_in_background(path, 7878)` 하드코딩을 `conductor_dashboard_port()`로
  교체. `porpoise dashboard` CLI의 `--port`는 그대로(우선) — 설정은 내장 기동 기본값.
- 설정 편집(config_edit): `EDITABLE_KEYS`에 `dashboard_port` 추가, `int_in_range`(1024..=65535) 검증,
  GET 응답·`read_config_json`에 노출. UI 설정 폼에 number 입력 추가.
- **공존 주의(문서화)**: 독립 대시보드를 `--port X`로 띄우고 launch로 spawn된 conductor가
  `dashboard_port=Y(≠X)`면 두 번째 대시보드가 뜬다 — 런처 흐름에선 `serve_dashboard=false` 권장(폼에서
  설정 가능). 코드 변경 없이 안내만.
- 단위 테스트: 기본 7878·범위 클램프·설정 파싱·화이트리스트 검증.

### M38-T02: 런 락 정밀화 + 강제 실행

**변경 파일**: `src/dashboard/launch.rs`

- **PID 생존 기반 판정**: run.lock에 이미 기록되는 자식 PID를 활용. `launch_blocked` 로직 교체:
  - live.json `run_active == true` → 차단(기존).
  - 아니면 락을 읽어: **PID가 살아있으면 차단**(spawn~`live::start` 공백 또는 진행 중), **죽었으면
    무시**(런 종료/자식 소멸 — 즉시 재실행 허용)하고 죽은 락은 기회적으로 제거.
  - spawn 직전 선점 락(pid=0)은 PID 생존 판정이 불가하므로 **시간 신선도(`LOCK_FRESH_SECS`)로
    fallback** — 짧은 TOCTOU 창만 덮는다(M37 선점 의미 유지).
- `pid_alive(pid) -> bool` 헬퍼(플랫폼 격리, 의존성 추가 없이 shell-out): Windows
  `tasklist /FI "PID eq N" /NH`, Unix `kill -0 N`(또는 `/proc/N`). 단위 테스트 대상 외(통합 하니스).
- **강제 실행**: `handle_launch` body `{"force":true}`면 락 차단을 우회(live `run_active==true`는
  그래도 막아 진짜 동시 실행은 방지 — force는 *stale 락* 전용). `parse_force(body)` 순수 함수 + 테스트.
- UI(T03와 별개): 409 응답 시 [함대 실행] 옆에 **[강제 실행]** 보조 액션 노출(force=true 재시도).
- 순수 판정(`pid==0 → 신선도`, `pid>0 → 생존`)을 테스트 가능하게 분리. 실제 PID 생존은 하니스.

### M38-T03: 재투입+실행 단일 버튼

**변경 파일**: `src/dashboard/static/app.js`

- 프런트엔드 전용(기존 엔드포인트 재사용 — 백엔드 변경 0). 리포트 FAIL 행 [재투입] 동작 확장:
  - 현재: `POST /api/control {redispatch}` 후 "예약" 토스트.
  - 변경: 오버라이드 기록 성공 후 **런이 비활성(`!run_active`)이면 곧바로 `POST /api/launch`** 호출
    → "재투입 + 함대 실행" 토스트. 런이 **활성이면** 기존대로 "다음 실행에서 적용" 안내(진행 중
    함대에 끼어들지 않음 — M37 범위 유지).
  - 라이브 상태(`run_active`)는 마지막 렌더 값 또는 즉석 `/api/live` 조회로 판단.
- 실패(재투입 또는 실행)는 단계별 토스트로 구분 표시. esc() 경유(XSS 규약).

### M38-T04: 설정 편집 주석·서식 보존

**변경 파일**: `Cargo.toml`, `src/dashboard/config_edit.rs`

- `toml_edit`(서식 보존 편집) 의존성 추가. `apply_updates`를 `toml_edit::DocumentMut` 기반으로 교체:
  기존 문서를 파싱→`[conductor]` 테이블의 해당 키만 set→to_string. **주석·기존 키 순서·서식 보존**.
  `[conductor]` 섹션이 없으면 생성. 빈 문서면 새 테이블.
- `validate_config_update`(검증·화이트리스트)는 무변경 — `toml::Value` 대신 `toml_edit::Value`로
  주입하거나 변환 계층 최소화(검증 출력 타입만 조정). 원자성(검증 실패 시 무쓰기) 유지.
- 단위 테스트 보강: 주석이 있는 workspace.toml 갱신 후 **주석이 보존**되는지, 타 섹션·키 순서 보존,
  화이트리스트 외 키 거부·무쓰기(기존 테스트 유지).

### M38-T05: 문서 + 하니스 (deps: M38-T01, M38-T02, M38-T03, M38-T04)

**변경 파일**: `docs/dashboard.md`, `scripts/dashboard-launch-validate.ps1`(확장), `scripts/dashboard-launch-live.sh`(신규)

- 문서: 포트 설정(`dashboard_port`)·공존 주의, 런 락 PID 판정·강제 실행, 재투입+실행 단일 버튼,
  설정 주석 보존을 `docs/dashboard.md` 런처 절에 반영.
- HTTP 하니스 확장(`dashboard-launch-validate.ps1`): ① `dashboard_port` GET/POST 왕복(범위 위반 400),
  ② 강제 실행 — stale 락 주입 후 `{force:true}` → 락 우회(단, run_active=true면 force여도 409),
  ③ 설정 POST 후 **주석 보존** 확인(주석 포함 workspace.toml에 POST → 주석 잔존), ④ 죽은 PID 락이
  차단하지 않음.
- **Unix 이식 라이브 하니스**(`dashboard-launch-live.sh`): `dashboard-launch-live.ps1`의 bash 포팅 —
  gate 모드 git 샌드박스 → launch → 자식 게이트 블록(비용 0) → 대시보드 kill → **자식 생존(`kill -0`)**
  → stop-next 정지. Unix `process_group(0)` detach 실측용(운영자 Unix 환경에서 실행).

## 완료 기준

1. `cargo build` 경고 0개, `cargo clippy` 신규 경고 0개, `cargo test` 전체 통과.
2. `[conductor] dashboard_port`로 내장 기동 포트가 바뀌고(기본 7878 유지·범위 클램프), 설정 폼에서
   읽기·쓰기 가능. `porpoise dashboard --port`는 기존대로 우선.
3. 30초 내에 끝난 런 직후 즉시 재실행이 가능하다(죽은 자식 → 락 무시). 진행 중(살아있는 자식/
   `run_active`)이면 여전히 409. stale 락에 막히면 **[강제 실행]**(`force:true`)으로 진행 가능하되,
   `run_active=true`는 force여도 차단(진짜 동시 실행 방지).
4. halt task 행에서 **한 번 클릭**으로 재투입 오버라이드 기록 후, 런 비활성 시 곧바로 함대가 기동된다.
   런 활성 시엔 "다음 실행에서 적용"으로 안내(끼어들지 않음).
5. 설정 편집 POST 후 workspace.toml의 **주석·타 섹션·키 순서가 보존**된다. 화이트리스트·검증·
   원자성(실패 시 무쓰기)은 M37과 동일.
6. 보안 무회귀: 신규/변경 쓰기 경로 모두 Origin(403)·스코프(404) 상속, 설정 화이트리스트 유지.
7. HTTP 하니스(포트·force·주석 보존·죽은 락) PASS, Unix 라이브 하니스(`.sh`)로 `process_group(0)`
   detach 생존 실측 가능(운영자 환경).
