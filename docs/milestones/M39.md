# M39 — halt 회복 지능: 정지 task 파킹·핫-재큐·적응형 재계획

## 목표

함대가 task 하나의 정지(halt)에 **멈추지 않고 회복**한다. 끝나면: max_redispatch를 소진한 task는
함대를 멈추는 대신 **파킹**되고 나머지 ready task는 계속 진행되며, 운영자가 보낸 재투입
오버라이드는 **실행 중 함대에 바로 반영(핫-재큐)**되어 다음 실행을 기다리지 않는다. 옵트인
설정(`auto_replan`)이 켜지면 정지 task를 **더 작은 하위 task로 자동 분할**해 "예산만 늘리는"
재투입을 "계획을 고치는" 회복으로 끌어올린다.

## 배경

retro(2026-06-11, v0.35.0 시점)가 집계한 **뿌리 A — "halt 이후가 빈약하다"**를 닫는다. 구체적 출처:

- **핫-재큐 미지원** (M37-impl 후속4, M37부터 최장 이월): 재투입(M37)은 "다음 실행에서 효력"뿐.
  실행 중 함대에 끼어들 수 없어, 정지 task 하나를 살리려면 함대 전체를 다시 띄워야 한다.
- **정지 = 함대 정지** (현행 코드): 순차 루프(`conductor/mod.rs`)는 `TaskOutcome::Halted`에서
  `break`해 **런 전체를 종료**한다. 병렬 루프(`parallel.rs`)도 stuck(attempts>cap) 시 `break`로
  런을 끝낸다 — 독립적인 다른 pending task가 남아 있어도 한 task의 정지가 전부를 멈춘다.
- **재투입이 "예산만 늘림"** (retro 회고 메모 1, M38-review): 같은 task를 더 큰 예산으로 재시도할
  뿐, 반복 실패의 원인(너무 큰 단위)을 손대지 못한다 → **적응형 재계획**이 이를 보완.

기존 자산 재사용: 재투입 오버라이드 채널(M37 `.porpoise/control/redispatch-<id>.json`,
`consume_override`), task 파싱·완료 표시·추가(`parse_tasks_from_project_md`·`mark_tasks_complete`
패턴·`append_milestone_to_project_md`), 검증 피드백 주입(`brief::with_feedback`), 마일스톤 세션의
LLM 호출 패턴. 설계 불변: project.md 쓰기는 `utils::fs::write_file`(루트 경계), 무결합(파일 매개) 유지.

## 태스크 상세

### M39-T01: 핫-재큐 — 정지 task 파킹 + 함대 계속

**변경 파일**: `src/conductor/mod.rs`, `src/conductor/parallel.rs`, `src/config/workspace.rs`

- `[conductor] park_on_halt: Option<bool>`(기본 **true** = 새 회복 동작) + getter. `false`면 기존
  동작(정지 시 런 종료)을 보존 — 하위호환 탈출구.
- **순차 루프**(`run_conductor_inner`): `parked: HashSet<String>` 도입. `conduct_task`가
  `Halted`를 반환하면 `break` 대신 **파킹**(`parked.insert(id)`, live "halted" 유지, halt 힌트
  저장) 후 **계속**. ready task 선택에서 parked 제외(`ready_tasks(...)` 후 `!parked.contains`).
  비-parked ready가 없고 parked가 남으면 → **revive 시도**(아래) 후 없으면 종료(parked는 incomplete).
- **병렬 루프**(`run_parallel`): 현행 `stuck → break`를 **stuck → parked 이동 + 계속**으로 변경.
  parked는 매 배치의 ready에서 제외. ready(−parked)가 비고 진전 없음 + parked 남음 → revive 시도
  후 없으면 종료.
- **override revive(핫-재큐 핵심)**: 루프 상단에서 **parked 각 id에 대해** `redispatch::consume_override`
  확인 — 있으면 예산 상향(M37 로직) + **un-park**(parked에서 제거, 순차는 재시도 대상 복귀, 병렬은
  attempts 리셋). 이로써 실행 중 보낸 재투입이 같은 런에서 즉시 반영된다.
- live.json은 parked를 "halted" phase로 유지(대시보드 호환). 무한 루프 방지: revive 없이 진전
  0이면 종료(기존 가드 유지). 순수 분리: "다음 착수 task 선택(parked·완료·deps 반영)" 로직을
  헬퍼로 빼 단위 테스트.

### M39-T02: 적응형 재계획 — 정지 task 자동 분할 (deps: M39-T01)

**변경 파일**: `src/conductor/replan.rs`(신규), `src/conductor/mod.rs`(파킹 경로 연동), `src/config/workspace.rs`

- `[conductor] auto_replan: Option<bool>`(기본 **false** — 옵트인, LLM 비용 유발) + getter.
- `replan.rs`:
  - `propose_subtasks(runner, parent_id, parent_title, feedback, diff, model, logger) -> Result<Vec<SubTask>>`
    — 검증 피드백·diff를 근거로 "이 task를 한 번에 끝낼 수 있는 **2~4개 하위 task**로 분할" LLM
    호출(구조적 출력 가능 시 사용, 아니면 줄 파싱). 2개 미만·실패면 `Err`/빈 → 호출자는 **분할 없이
    파킹으로 폴백**.
  - `insert_subtasks(path, parent_id, parent_title, subtasks) -> Result<Vec<String>>` — project.md에서
    부모 `- [ ] {parent}:` 줄을 `- [x] {parent}: [분할→{ids}] {title}`로 치환(완료 처리해 재시도
    배제·추적 보존)하고, 하위 task를 `- [ ] {parent}-S1: ...` 형식(부모 id + `-S{k}` 접미)으로 추가.
    `M..-T..-S1`은 기존 파서(`M`+`-T` 포함)에 유효. 쓰기는 `write_file`(경계). 순수 분리·단위 테스트.
- **연동**(파킹 경로, T01): 정지 task에 대해 `auto_replan`이 켜졌고 **아직 분할된 적 없으면**
  (id에 `-S` 미포함 + 재분할 마커 없음) `propose_subtasks` → 성공 시 `insert_subtasks` → 부모는
  완료·하위 task는 pending으로 루프가 이어받음(파킹 해제). 실패면 일반 파킹.
- **무한 분할 방지**: `-S` 접미 task(이미 하위 task)는 재분할하지 않고 파킹만. 분할은 깊이 1로 한정.

### M39-T03: 위생 — `lock_blocks` 순수/부수효과 분리

**변경 파일**: `src/dashboard/launch.rs`

- 현행 `lock_blocks`는 판정 + 죽은 락 삭제(부수효과)를 한 함수에서 한다(M38-review 권장1). 분리:
  - `lock_verdict(content, now, pid_alive: bool) -> LockVerdict { Blocked, Stale, DeadPrune }` — **순수**
    (pid 생존 결과를 인자로 주입 → shell-out 없이 dead-PID·선점·신선도 분기를 단위 테스트).
  - `lock_blocks(project)` — 파일 읽기 + `pid_alive` 호출 + `lock_verdict` 적용, `DeadPrune`이면 락 제거.
- 동작 무변경(리팩토링), 단위 테스트로 dead-PID/선점/신선도 3분기를 shell-out 없이 검증(M38은 실
  `tasklist`에 의존). `pid_alive` 캐시는 호출 빈도가 낮아(사용자 클릭) 본 마일스톤 범위 밖(주석만).

## 완료 기준

1. `cargo build` 경고 0개, `cargo clippy` 신규 경고 0개, `cargo test` 전체 통과.
2. 정지 task가 발생해도 **함대가 멈추지 않고** 나머지 ready task를 계속 처리한다(`park_on_halt=true`,
   기본). `park_on_halt=false`면 기존 "정지 시 런 종료" 동작이 보존된다.
3. 실행 중 정지(파킹)된 task에 재투입 오버라이드가 도착하면 **같은 런에서 un-park·재시도**된다(핫-재큐).
4. `auto_replan=true`에서 반복 정지 task가 **2~4개 하위 task(`-S1`…)로 분할**되어 부모는 `[분할됨]`
   완료로 표기되고 하위 task가 이어서 처리된다. LLM 분할 실패·`auto_replan=false`면 일반 파킹으로 폴백.
   하위 task(`-S`)는 재분할되지 않는다(깊이 1).
5. `lock_blocks`가 순수 판정(`lock_verdict`) + 부수효과로 분리되고, dead-PID/선점/신선도 3분기가
   shell-out 없이 단위 테스트된다. launch 동작은 무변경.
6. 대시보드가 파킹 상태를 "재투입 대기"로, 분할 부모를 분할 표식으로 노출하고, 설정 폼에서
   `auto_replan`·`park_on_halt`를 편집할 수 있다(화이트리스트·검증 상속).
7. 단위·합성 하니스(파킹→revive, `insert_subtasks` 왕복) 통과. LLM 분할 제안은 운영자 라이브 검증 항목.
