# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-11 (v0.37.0 시점) — M37~M40 누적

### 집계 범위

tide `docs/` 체계 마일스톤 **M37~M40**(4개), impl 보고서 4 + review 보고서 4, 릴리즈
**v0.34.0~v0.37.0**. 직전 회고(v0.35.0 시점)는 M37~M38만 봤으나 이후 M39·M40이 더해져
**런처(M37·M38) → halt 회복(M39) → 비용(M40)**의 한 흐름을 가로질러 볼 수 있다.

### 반복된 문제·이슈 군집

- **운영자 라이브 실측 의존이 매 사이클 누적** (등장: M37·M38·M39·M40) — 실 spawn·OS detach·
  실 dispatch 실패·실 LLM 비용/파싱은 단위·HTTP 하니스로 못 덮어 매 review가 "운영자 라이브"
  항목을 남긴다. **가장 강한 반복 패턴.** 처리 추이: M37 Windows detach·M40 verifier 파싱은
  라이브로 **수정/확인**, 나머지(Unix detach·파킹 e2e·fast→strong 승급)는 **이월** 누적.
- **"동작 변경 + 하위호환 탈출구"** (등장: M39·M40) — 두 사이클 연속 기본 동작을 개선 방향으로
  바꾸되 설정/스키마로 구 동작 보존. M39 `park_on_halt`(정지=종료 → 파킹·계속, false로 복원),
  M40 `total_cost`(dispatch → dispatch+verifier, 구 레코드 불변). 처리: **수용**(⚠️ 문서화 + opt-out).
- **동시성·종료 안전성 결함을 impl 중 선제 수정** (등장: M37·M39) — 리뷰 전에 구현 중 잡아 고침:
  M37 함대 실행 TOCTOU(락 선점), M39 병렬 파킹 무한 재시도(dispatch 오류 카운트). 처리: **수정**.
- **무결합(파일 매개) 경계 유지** (등장: M37·M38·M39) — 설정 쓰기 화이트리스트·PID 락 launcher-side·
  파킹 상태기계가 모두 "conductor 무결합" 제약 아래 설계됨. 처리: **수용**(경계 명시).

### 수용된 트레이드오프

- **M37**: run.lock 30초 시간 기반(짧은 런 quirk) → **M38에서 PID 기반으로 해소**.
- **M38**: PID 재사용 과차단(force 우회), `pid_alive` shell-out 비용, toml 주석 손실(→M38 toml_edit 해소).
- **M39**: `park_on_halt` 기본 동작 변경, replan이 diff 미사용(plumbing 회피), `insert_subtasks` 파일끝
  삽입, `parked` in-memory(런 한정), `auto_replan` LLM 호출 무게이트·무계측.
- **M40**: `total_cost` 의미 변경(dispatch+verifier), 라우팅이 attempt 기반(난이도 사전추정 아님 —
  fast 실패 잦으면 비용↑), 무용한 `run_agentic` 제거. 비결정·실비용 라이브 하니스는 커밋하지 않음(수용).

### 회고 메모

1. **미반영 후속이 거의 전부 "운영자 라이브 실측"으로 수렴** — 코드 task가 아니라 이월 표에서 안
   빠진다(Unix detach·파킹 e2e·실 비용/승급). 개별 마일스톤에 끼우지 말고 **"라이브 검증 세션"을
   한 번 잡아 일괄 소진**하는 게 효율적. (단 M40에서 보듯 비결정·실비용이라 1회성 수동.)
2. **후속 흡수율이 매우 높다** — M37의 후속 4건이 M38에서 전부, M39의 비용 계측이 M40에서 반영.
   tide 루프(출시→마감 페어)가 잘 작동. 다만 **retro 두 뿌리가 다 해소돼 다음 큰 방향이 비어 있음** →
   라우팅 고도화는 점진적일 뿐, 새 비전/사용자 요구가 필요한 시점.
3. **"동작 변경 + 탈출구"가 2연속**(park_on_halt·total_cost) — 누적되면 기본 동작이 조용히 달라진다.
   릴리즈 노트 ⚠️ 표기를 일관 유지하고, 언젠가 "기본값/스키마 정리" 마일스톤을 고려.
4. **비결정·실비용 라이브 검증은 1회성 수동, 커밋 하니스는 결정적인 것만** — M40에서 확립한 원칙
   (감사 레코드 즉시 종료로 비용 캡, flaky 하니스는 비커밋). 향후 verifier/모델 변경 시 동일 적용.

## 2026-06-11 (v0.35.0 시점)

### 집계 범위

명확한 페어라 "출시→잔여 품질 마감"의 한 묶음으로 읽을 가치가 있다.
(porpoise 네이티브 `.porpoise/milestones/` M1~M36은 gitignore·tide 체계 밖이라 회고 입력에서 제외.)

### 반복된 문제·이슈 군집

- **동시성·런 락 정확성** (등장: M37, M38) — 런 락이 두 사이클 연속으로 다듬어졌다. M37: 가드
  확인 후 spawn·이후 락 기록의 **TOCTOU 경쟁**(동시 요청 이중 spawn) → 리뷰 중 락을 spawn 전
  선점으로 **수정**. M38: 시간 기반(30초) 만료가 짧은 런 직후 재실행을 막던 **quirk** → **PID
  생존 기반**으로 **수정**. 추이: 둘 다 수정. 교훈 — 동시성 가정은 라이브/실사용에서 드러난다.
- **detach·spawn 성공 경로가 자동 테스트 밖** (등장: M37, M38) — 실제 spawn은 conductor 런·claude를
  띄워 no-claude HTTP 하니스로 못 덮는다. M37: 라이브 `.ps1`로 **Windows 실측**(gate 블록 → 비용
  0 → 대시보드 종료 후 생존). M38: `.sh`로 **Unix 이식**(작성·미실측). 추이: 라이브 하니스로 점진
  해소, **Unix 실측은 이월**.
- **무결합(파일 매개) 경계 유지 부담** (등장: M37, M38) — 두 사이클 모두 "무결합 원칙 유지선"이
  설계 제약으로 등장. M37: 제어 쓰기를 control/ 한정 → 설정(config)으로 **의도적 확장**(화이트리스트로
  제한). M38: run.lock을 conductor가 모르게 **launcher-side PID 판정**으로 유지. 추이: 원칙 유지하며
  **수용**(범위를 명시적으로 한정).

### 수용된 트레이드오프
